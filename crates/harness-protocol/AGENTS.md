# crates/harness-protocol

## Purpose

This crate defines wire types for every harness component. These include the event envelope and `/v1` and `/internal` API types. They include DynamoDB items and the S3 layout. They include the model catalog row, evidence header, and engine profile. They include the AgentCore Runtime contract and the direct-run contract. The crate also exports their JSON Schema and OpenAPI definitions.

## Ownership

`crates/AGENTS.md` owns this crate. The generated files under `schemas/` belong to this crate. The crate is in agentd's crate closure. A change here therefore moves the worker image key.

## Local Contracts

- No I/O and no AWS SDK dependency; serde and schemars types plus pure validators. The only
  file writes are in the `export-schemas` binary.
- Build target: `build.rs` reads the repository's `accounts.json`
  and selects
  one entry with `accounts::select_account` (`HAMH_AWS_PROFILE` names it by profile; unset or empty:
  the one `active` entry; `accounts::parse_accounts` applies the file rules of
  `scripts/lib/aws_target.py`: `role` is `active`, `history` or `test`, and a `test` entry never counts as the active one). It generates `target::{E2E_ACCOUNT, E2E_REGION, E2E_PROFILE,
  OPERATOR_POOL_MEMBER, OPERATOR_POOL_MEMBERS, SELECTED_BY, ACCOUNTS}`; a malformed file or an unknown profile fails the build. The optional `operator` field of an entry
  (`accounts::Operator`, parsed by the rules of `scripts/lib/aws_target.py` and `infra/lib/operator.ts`, which share the table `infra/test/fixtures/operator-identity.json`) decides the pool
  member: `accounts::operator_pool_members` gives the caller pattern of a role (`arn:aws:sts::<account>:assumed-role/<name>/*`) or the two user ARN forms of a user, and the IAM role `Admin`
  for an entry without the field. `OPERATOR_POOL_MEMBER` is the first pattern and `OPERATOR_POOL_MEMBERS` lists all of them. Every crate takes the account,
  home Region and default profile from these constants; a binary serves the entry it was built
  for. `src/accounts.rs` is shared with `build.rs` through `include!` (no inner doc comment, no
  `crate::` path). The schemas never embed the selection: `schemas/` is the same bytes under
  every `HAMH_AWS_PROFILE`.
- Modules: `envelope` defines event types in architecture table order. It includes each event's required authority and `validate`. Only harness events change goal status or show links. Inline payloads allow at most 4,096 bytes of compact JSON. Larger payloads use an S3 claim check. `api::v1` and `api::internal` define API bodies. They include the `V1_ROUTES`/`INTERNAL_ROUTES` tables. `store` defines items that derive `PK`/`SK` through `Keyed`. `TURN#<agentId>#<n>` uses zero-padding to 6 digits. The event shard is FNV-1a 64 of the agent id mod 32. Harness events use shard 0. This module also includes S3 key helpers. `catalog` defines `CatalogRow` and `ExcludedModel`. `Protocol` is `converse`, `converse-relay`, `mantle-responses`, or the fork's `mantle-chat`. Both Mantle choices need a `routeFamily`. `target` parses `cc:`, `gh:`, and `gl:`. Only `cc:` is served. `gl:` is not built:. Therefore, repo-gateway refuses both at the run's first state. The unknown-scheme error names `cc:` only. The schema description string stays as released. `research_copy` is the pure exact-copy rule for stored third-party files: `COPY_FLOOR_BYTES` (1 KiB of the stored file) and `COPY_NORMALISED_FLOOR_BYTES` (512 bytes: a stored file whose normalised form is shorter has no normalised hash and matches the same bytes only, so a file padded with blanks cannot make a short ordinary file look like a copy), `is_exempt_path` (licence texts, `.gitignore`, `.editorconfig`, lockfiles and minified files, on either side), `normalise` (byte order marks, trailing blanks, CRLF and the final newline made alike; idempotent), `StoredFile` with its two hashes, and `CopyIndex::find` (exact, then normalised). It has no wire type and no schema, so it carries no version bump; the bundle validator and `ham-research check` run the same code. Other modules include `goal` and `common`. `engine_profile` defines the profile file type. ACP launch is required. CLI is optional. The type uses `deny_unknown_fields`. Semantic checks live in `harness-core::engine_profile`. `orchestration` defines payloads for harness events that `ham` reads. `runtime` and `direct` define the AgentCore Runtime contract. Other modules include `accounts` and `export`.
- Engines as profile names: `common::Engine` is the name of a profile `engine/profiles/<name>.toml`, not a closed
  enum. A name is 1 to 32 bytes, a lowercase letter then lowercase letters, digits and hyphens
  (`ENGINE_NAME_PATTERN`, the schema's `pattern`); `Engine::new`/`FromStr` refuse anything else
  (`EngineNameError`), serde reads and writes the bare name, so every 1.x record (`"cline"`,
  `"opencode"`) is unchanged on the wire. It is `Copy` (stored inline) and ordered by name;
  `Engine::CLINE` and `Engine::OPENCODE` are constants usable as `match` patterns, and a match on an
  engine needs a `_` arm for the others. Whether a profile exists is checked where profiles are
  known (harness-core `engine_profile::known_engine`), not here. `DirectInvocationRequest.engine` stays a string
  on the wire, and `validate_direct_invocation` refuses one that is not an engine name (`BadEngine`) before
  agentd opens `<profiles>/<engine>.toml`.
- Every exported schema has an `insta` snapshot in `tests/snapshots/`, and `schemas/*.json` must
  equal fresh output; regenerate with `cargo run -p harness-protocol --bin export-schemas`. The nine files are in
  `export::SCHEMA_FILES`. `tests/schemas.rs` pins each released protocol version with the SHA-256 of its contract files (`FROZEN`): a change to
  any artifact needs a version bump, a new `FROZEN` line (pin a new version by appending it; never edit a released line) and a
  contract-test update.

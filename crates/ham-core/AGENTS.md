# crates/ham-core

## Purpose

This crate holds the state of the `ham` thin client. It includes control-plane event reducers, the agent table, the command parser, the command registry and the chat box's router. It includes request building and download planning. It includes the bounded gzip reader, the stored conversation's chunk format with the transcript route's wire types, and chat-content search. It includes the client file `config.toml` with the comment-keeping editor of its text, and plain-text renderings. It includes the pure core of run names and of the utility model that writes them. It has no agent logic (invariant 5). It has no terminal, network or AWS code. Its local files are the user's own text and downloads: `config.toml`, the rules directory with `continue.md`, the skills directory and one file for each engine in `engines/` (`engine_file`), all under `~/.config/ham/`.

## Ownership

Owned by `crates/AGENTS.md`.

## Local Contracts

- `state::RunState` stores accepted envelopes keyed by ULID. It builds `RunView`, the run view, by folding envelopes in ULID order. Duplicate, reordered and gapped delivery across the 32 shard cursors converge. Envelopes failing `harness_protocol::envelope::validate` are rejected. Agent-authored `goal.status`, `goal.blocked`, `delivery.*` or `run.completed` never change status. They never show a link (invariant 4). `RunView::untrusted` counts them. A terminal status never reopens. `RunState::accepted` yields accepted envelopes in ULID order. The view holds the status and phase. It holds the PR link from `delivery.pr`. Otherwise, it uses the `prUrl` of `delivery.ready`. It holds the zip (`ZipLink`). It holds one `AgentLine` per agent. Each row holds the engine and model. It holds the latest summary of `turn.progress`, `tool.summary` and `turn.ended`. It holds the turn count. It holds the effective context window of `session.started`. A window of 0 is none. The view holds the blocked reason and the result of `run.completed`, with the `observations` of that event. `render::final_card` prints each as an `Observed` line directly under `Outcome`. A task-level `goal.status` or `goal.blocked` is ignored. A task-level event has a `taskId`. A harness `run.aborted` means the run's root execution ended early. It makes the view `cleared` and sets `RunView::aborted`. This holds sanitized `AbortedView {status, error, cause, stoppedAt}`. Its `line()` is `<STATUS>[ <error>][: <cause>]`. `AbortedView::of` reads a summary's `aborted`. `RunView::windows()` carries each model's largest effective context window. Any other event type is accepted and changes nothing. The fields read from payloads are documented atop `src/state.rs`. `harness_protocol::orchestration` holds the harness payload types. Tests are in `tests/state.rs`. `tests/convergence.rs` proves the view for any interleaving, duplicate and gap across the 32 shard cursors.
- Tool calls and notices in the run view: `RunView.tools` holds one `ToolRow {call_id, title, kind, status, event_id}` per
  tool call, in the order the calls began. `ToolTracker` (the one fold the run view and the chat view share) joins a `tool.summary`
  {toolCallId?, title, kind?, status?} and the later update of the call, a `turn.progress` {toolCallId, status} with no `kind`, by `toolCallId`.
  A call only moves forward (`merge_status`: pending, then in_progress, then completed or failed; a later finished status replaces an
  earlier one; the recorded stream has the summary's `pending` arrive after the `in_progress` update); an update that comes before its summary
  makes an untitled row that the summary fills; a summary with neither title nor id (the old `text` shape, which agentd never wrote) makes no
  row. The title is the agent's newest words in the dashboard's LAST column. `RunView.notices` lists, in event order, the provider and engine
  notices of `notice` below; `RunView.route` (`RouteStatus`: the model after the latest `provider-switch`, the switch count, the retry in
  progress, a wait, an outage) feeds `RunView::route_line()`, the status line's route part (`running on GPT-6.1 Sol after 2 switches`,
  `provider error, try 2 of 4`, `waiting on the model provider`, `every model route down for 30 min`); a message tail, a tool event or a
  new turn clears the retry and the wait, and a `new-session` event clears the route model too (agentd begins a fresh session on the route the
  user chose; `crates/agentd/src/direct/fresh.rs`). Two readers serve the chat view: `RunView::route_trouble` is the trouble part alone (the
  header adds it next to the state; the header names the model in use itself) and `RunView::route_now` is the route line for the status
  block's Route row; both are `None` once the run is over (`run.completed`, `run.aborted` or a terminal goal status), because a retry that was
  the last event before the end is no longer going on and the `Ran on` row says where the run ended. Tests: `tests/tool_rows.rs` (the fixture `tests/fixtures/tool-events-recorded.ndjson` holds the
  payloads of a recorded run, verbatim for the four calls whose summary the event dump kept whole; the envelope ids are minted
  again), `tests/notices.rs`, `tests/state.rs`.
- `notice`: `notice_of(&Envelope) -> Option<Notice {event_id, ts, kind, text}>` gives one plain line, at most 160 characters,
  terminal safe and redacted, for each thing agentd writes besides the conversation: `turn.progress` kinds `provider-retry`
  (`Provider error (temporary): try 2 of 4 in 12 s. <detail>`), `provider-switch` (`Switched to another model (switch 1): Claude Sonnet 5.5 to
  GPT-6.1 Sol, after a temporary failure.`; the ids when both routes have one name), `engine-stop`, `notify` (outage, history_unusable, other),
  `provider-wait`, `provider-outage`, `report`, `permission.requested`, and the question and answer kinds (`needs-input`, `input-received`,
  `input-ignored`, `input-closed`, `new-session`, which use the event's own `text` where agentd wrote one). A kind this client has no name for is
  `NoticeKind::Other` (`Event <kind>`). No text names an engine; the lines say what happened to the run and never judge the
  work. `tests/notices.rs` pins each line and reads `crates/agentd/src/direct/collector.rs` to check that every member the client reads is
  still written next to its kind word; the question and answer kinds read the golden files of `fixtures/direct-input/`.
  The goal loop: `turn.progress` kind `goal-loop` with a `phase` gives `NoticeKind::GoalLoop` (`on`, `kick` as `Goal loop: continue sent.`, `done` as `Goal loop: Cline
  called the goal-complete tool.` plus ` Cline's summary: <summary>` when there is one, and a phase this client has no name for), `GoalRound` (`Goal loop: N rounds ended, the last one completed.`, built from `rounds`
  and `status`, never from the event's text; the chat model keeps ONE block `goal:rounds` that a later round event replaces), `GoalBrake` (the event's `text` up to ` Its words:`) and `GoalQuiet` (`off`, `fallback`, `rearm`: the
  event's own words, drawn dim). `goal_blocked_line(&Envelope)` returns the engine's quoted line of a `blocked-twice` brake when it begins `BLOCKED:`; the chat model adds it as a `GoalBlocked` block after the brake block and the
  transcript draws it bold. None of these is a run notice (`is_run_notice` is false), none says that work was checked, and `run.completed` still gives the label of the run. `tests/goal_loop_notices.rs`.
- The research lines: `turn.progress` kind `research` gives `NoticeKind::Notify`: with `phase: "off"` the event's own sentence ("Research off: you switched it off for this run."), and the event agentd posts at the end of a run that made calls gives a line built from the numbers alone ("Research: 3 searches, 2 page fetches, 1 repository download, 3 items stored, 1 error."). `tests/research_notices.rs`.
- `sanitize` for the transcript: `display_text` and `display_line` strip what `sanitize` strips (every C0 and C1 control except
  newline and tab, so carriage return, backspace, bell and DEL go; every escape sequence with its payload, so an OSC 8 link or an OSC 52
  clipboard write leaves only its visible text) and show bidirectional controls, zero-width and other invisible format characters and the
  Unicode tag characters (an invisible copy of ASCII) as `<U+XXXX>` markers (`marker`): U+200B, U+200E, U+200F, U+2060, U+FEFF, U+061C, U+00AD,
  U+2061 to U+2064, U+206A to U+206F, U+180E, U+FFF9 to U+FFFB, the Hangul fillers, the Braille blank U+2800, the combining grapheme joiner
  U+034F, U+17B4, U+17B5, the Mongolian selectors, the variation selectors U+FE00 to U+FE0F and U+E0100 to U+E01EF, and the musical and
  Egyptian format controls. A BEL ends an OSC string only; a DCS, SOS, PM or APC string ends at ST. An escape sequence of intermediate
  bytes and a final byte (`ESC ( B`, `ESC $ ( B`, `ESC # 8`) goes whole; an 8-bit SOS, PM or APC goes with its payload when an ST closes
  it and alone when none does. The joiners U+200C and U+200D stay only between two characters of a shaping script (emoji and symbols,
  Arabic and Persian, the Indic and South-East Asian scripts; Latin, CJK and Braille are not), and U+FE0E and U+FE0F stay only once, right
  after such a character, because anywhere else they could only carry hidden data. U+2028
  and U+2029 become newlines, a run of combining marks (the common blocks, Hebrew points and Arabic marks) is cut to `COMBINING_MAX` (3)
  whatever joiners or selectors sit between, URLs stay plain text, and the result is stable (`display_text(display_text(x)) ==
  display_text(x)`). `sanitize` and `sanitize_line` (titles, single-line cells) are unchanged apart from the string and escape rules above.
  `redact::redact_tokens` is the display-side backstop to the worker's redaction: it hides GitHub, GitLab, Slack, Google, npm and
  OpenAI-style tokens, AWS access key ids (AKIA and ASIA; role and user ids are kept), JSON web tokens, bearer and basic credentials (any
  spacing; an `Authorization` header needs no minimum length, a bare `Bearer` needs 16 characters with a digit or symbol), private key
  blocks (RSA, EC, OpenSSH, PGP), a password in a URL, a presigned or signed query string (AWS, CloudFront, Google Cloud Storage, Azure)
  and the value of a credential-named setting (`[redacted]`), and leaves commit hashes, ULIDs, UUIDs and prose alone. Its scan is
  linear: `redact_with_work` counts the steps, and a test holds pathological text (repeated `?`, `password=$`, `eyJ-`, `github_pat_`,
  `://`) to 64 steps per character. Tests: `tests/sanitize_display.rs`,
  `tests/redact_display.rs`
  (every fake secret is built at run time).
- `search`: search inside one chat. `find_ranges(text, query)` gives the non-overlapping, leftmost matches of a query as character ranges,
  ignoring case (`char::to_lowercase`, plus `ß` as `ss`, the long s and the final sigma; no Unicode normalization); the scan is Knuth-Morris-Pratt, linear in the
  text (`find_ranges_counted` counts the steps), and a query that is empty or only blanks finds nothing. `search_blocks(&ChatModel, query)` and `ChatSearch`
  look at what the transcript draws (`display_line` of a head, `display_text` of a body; never the role word or the progress-feed label) and give `Hit
  {block, id, part: Head | Body, range, nb_start, nb_len}`: the non-blank characters before the match (head first) and in it, which is how the widget finds
  the wrapped row and paints the cells whatever the width. At most `MAX_MATCHES` (10,000) hits are kept (`truncated()`, `1/10000+`); a query is cut at
  `MAX_QUERY_CHARS` (256). `ChatSearch` is the state machine: `open(ScrollMark)`, `key(Key, &ChatModel) -> Vec<Effect>`, `next`, `prev`, `model_changed`,
  with `phase()` (Idle, Editing, Active), `is_active()` (true while typing too), `takes_text()` (Editing), `walks_matches()` (Active: the only phase in which `n` and `N` mean next and previous), `query()`, `hits()`, `current()`, `count_text()` (the position and the total joined by a slash, or `no matches`), `bar_text(width)`, `wrapped()` and
  `blocks_scanned()`. `Effect::Show(Hit)` asks the screen to bring a match into view (open its block first when it is folded);
  `Effect::Restore(ScrollMark)` asks it to put the view back (`ScrollMark {top_line, following, selected, anchor}`). A longer query is searched only in the
  blocks that held the shorter one while the chat has not changed (a fingerprint of block ids and revisions; a shortcut for the ordinary case), and never after a cut hit list; `model_changed` on an unchanged chat does nothing (`blocks_scanned()` is 0). The matcher takes a folded letter whole: after a match ends inside one (the second `s` of `ß`) the next match starts at the next character. Tests:
  `tests/search.rs` (tables and proptest for the matcher, hits, state machine, narrowing counters).
- `runfilter`: the Runs screen's filter, pure. `RunRow::from_summary(&RunSummary)` words a run for the screen
  and sets its `Gutter`: `Failed` (the run
  ended early or the harness blocked it), `NeedsYou` (an open question on a run that is not finished), `Running` (active), else none; `Gutter::glyph` is
  one ASCII character (`>` `!` `x` or a space) and `word` is `running`, `needs you` or `failed`. `RunsFilter` takes the text of the find-or-command box:
  every word must be found, ignoring
  case and with the matcher of `search`, in the id, the status words (a waiting run also reads `needs input needs you`, a failed one `failed`), the target,
  the title, the name, the model or one of the tags; `RunsFilter::set_tags` picks tags (AND, each exactly as the row shows it, a tag named twice once), `tags` gives them, `is_narrowed` counts them and `clear` empties the words, the scope and the picks together; `RunRow::label` is the name, else the title, else nothing; `IndexEntry` (what a list read holds about one run) carries `name` and `name_source` beside the title and the model, and `tags` (`Option<Vec<String>>`: `Some` is final, `None` is a backend without tags); `visible(&[RunRow])` gives the indices in list order, `highlight(text)` the merged character ranges to mark in a cell,
  `summary(shown, total)` the line under the list (`10 of 300 runs match "calc"`, `4 of 300 runs in cc:calc`, `no run matches "x" (300 runs)`, and with picked tags `12 of 212 runs match +project:billing-export`, the words quoted before the `+tag` tokens);
  `toggle_scope(focused)` limits the list to the focused run's project and turns it off again without a focused run (`Scope::{All, Project}`);
  `select_after(rows, visible, selected_id, prev_pos)` keeps the selection on its run when the list changes. Refresh: `Refresh::Timer.pages()` is
  `Pages::First` (the newest `FIRST_PAGE` = 100 runs) and `Refresh::Manual.pages()` is `Pages::All`; `merge_first_page(old, page, has_more)` lays a
  refreshed first page over the held list (the next token, not the page length, says whether more follow: control-api skips a run item it cannot
  parse, so a page can be short with a next page behind it; created times are compared as times, a fraction ignored); `RunsRead::{First {runs, has_more}, All(runs)}.apply(&held)` is the
  merge made when a read is applied (`Api::read_runs(Refresh)` in the ham crate returns it); `newly_needing_you(old, new)` names the runs that began to wait for the user, for the bell.
  `router::is_command_attempt(text)` is the one test of "starts like a command" that the box and the Runs filter share. `RunsFilter::scope_key_labels(focused)` returns the wordings of the `p` key from the longest to the shortest (limit off: `p only cc:calc` with the project text `cc:<name>` whole up to 24 characters and, above that, its first 23 characters and an ellipsis (pinned for 24, 25 and 100 characters and for wide characters), `p this repo`, `p repo`; a run with no repository: `p only s3-only`, `p s3-only`; limit on: `p show all runs`, `p all runs`, `p all`), which the Runs screen takes the first of that fits the room its key line has; `position_text(at, of)` is `run 12 of 769` for the border of the table. Tests: `tests/runfilter.rs`, `tests/runfilter_key_label.rs`.
- `tagexplore`: the model of the tag explorer overlay of the Runs screen, pure. No terminal, network or AWS code and nothing on
  disk: the client draws what it returns and sends the edits. It reads only the rows the client already holds. `Held {run_id, created_at, tags}` is a held row (`created_at`
  RFC 3339 UTC, `tags` the effective tags). `TagIndex::build(&[Held])` reads the rows once: the first listing of a run id counts, and a tag named twice on a run counts once. A
  tag that is not printable ASCII without a space, is longer than `MAX_TAG_LEN` (128) bytes, or is changed by `redact::redact_tokens` is never counted, picked or drawn (so no escape
  sequence, control, invisible, wide or look-alike character gets through); `dropped()` counts those tag occurrences, and a run left with no tag counts as a run without tags. A pick
  that is not such a tag is ignored by `view`, `matching` and `note_text` alike, so no pick filters the runs without a row that shows it.
  `view(picks, find, now) -> View {rows: Vec<TagStat {tag, runs, last}>, matched, held, tag_count, untagged}`: picks are AND, `matched` counts the runs that hold every pick (all
  runs with no picks), and the `runs` of each row count only inside those runs, so counts narrow as tags are picked; `last` is the age of the newest of them. Order: picked tags
  first, then `runs` descending, then the newest run, then the tag text. A tag with no run in the result is hidden unless it is picked; a picked tag that no run matches stays
  with `runs` 0 and an empty `last`, so it can be dropped. The find line cuts only the table: it never changes `matched`, `held`, `tag_count` (the tags before the cut) or
  `untagged` (every held run without a tag, whatever the picks), and it never cuts a picked tag. `matching(picks)` gives the run ids that hold every pick, in row order (none when a
  pick is no held tag). `find_matches(tag, find)`: every word must occur in the tag, ignoring case as the Runs filter does (`search::fold`); a word that starts with `^` must begin
  the tag; an empty find or a lone `^` passes everything; the find is cut at `search::MAX_QUERY_CHARS` and a repeated word counts once. `age_text(now, created)` gives `59s`, `59m`,
  `23h`, `13d`, then weeks (`2w` from 14 days, up to `99w`), then years (`2y`, rounded, at most `9999y`), so it never needs more than five columns; a time in the future is `0s` and a
  time that cannot be read is `-`. `remove_plan(tag, rows)` lists the run ids that hold exactly that tag, each run once, in row order; `batches(ids, n)`
  cuts them in order into batches of at most `n` (0 is 1; the edit route takes 40, so 85 ids give 40, 40 and 5). `note_text(&View, picks)` words the line under the table as the
  Runs summary does, with U+00B7 between the parts: `212 runs · 41 tags · 30 have no tags` (the last part only when `untagged` is above 0), `12 of 212 runs match
  +project:billing-export · 10 tags`, `no run matches +tech:go (212 runs)`; picks the table could not show are left out of the line. The tag grammar and the effective tags are not decided here;
  this module counts what it is given. The tests include a proptest that compares `view` and `matching` with a plain second implementation, and a size test: 10,000 rows of 4 tags
  must build in 200 ms and a view must take 50 ms.
- Plain phrases: `registry::PHRASES` is the fixed table of five whole-line phrases (`push my code`, `push this run`, `pull the zip`, `show my runs`, `cancel this run`) and the built command each proposes; no phrase is one

  newest first, each text once; the first Up keeps `current_text` and its taint as the draft and skips entries equal to it; walks a snapshot), `next` (Down; below the newest
  the draft comes back with the taint it had), `cancel -> Option<Draft {text, tainted}>`, `is_browsing`; a prompt of an earlier run is only its first 2,000 characters until
  its full text is fetched: while `pending_full` names a run the screen must not send the box, `supply_full(run_id, full_prompt)` refuses a text that the short form does not stand for (a `Head` must begin the prompt; a `Title`
  must be the title of it by `run_index::title_of`, the server's rule, checked on the prompt as it arrived and as it is stored, because the title is cut at 80 characters with an ellipsis and a control

  the recall to show, whose `replaces` is the short form (the screen replaces the box only if it still holds exactly that), `forget_pending` when

  `SESSION_MAX_BYTES` = 8 MiB (the newest prompt always); text from the server (`Earlier::from_prompt`, `set_run_messages`) is cleaned of escape sequences and controls. `Recall {text, fetch_full, tainted}`:
  every text from the history is tainted. `search(draft, tainted) -> ReverseSearch` is Ctrl-R over a snapshot (a full prompt that arrives later is not in it): `type_char`, `backspace`, `clear`, `older`

  `router::split_words`: quotes and backslashes only, nothing expanded, control characters refused), `edit_with(&Editor, draft, dir, run)` where `run(&mut Command) ->
  io::Result<ExitStatus>` starts the child (the TUI passes a closure that calls `suspend_for`; `edit(..)` just runs it; `edit_with_report` also says how long the editor ran, and

- `meters` and `alert`: the status line, the reconnect overlay and the bell, pure, with the clock passed in. `elapsed_s(started, ended, now)` (stops at the
  end of the run, never negative) and `age_s(last_read, now)`; `tokens_text(n)` (`999`, `1.5k`, `113k`, `1.3M`). `StatusLine {model, state, elapsed_s, tokens, cost,
  as_of_turn, live, context: Option<Context {used, window}>, age_s}.line(width)` words `Claude Sonnet 5.5 · active · 12m40s · 113k tok · $0.14 · as of turn 3 · ctx
  [####------] 42% · updated 2s ago`: the totals are those of the last completed turn and say so unless `live` is set,

  and the model, and only then is cut; text handed in is cleaned and redacted. `Link` is the reconnect state machine: `on_ok(now_ms)`, `on_err(now_ms)`, `state(now_ms)` (`Connected`,
  `Quiet`, `Lost {for_ms, first_connect}`), `overlay(now_ms)` (`Connection lost, retrying (12 s)`, or `Cannot connect yet, retrying (5 s)` before any good read; it shows after

  `observe(&[ids that wait])` returns an `Alert {run_id, bell, notify, tmux}` for each id that did not wait at the last call (one bell for the batch; the bell can be switched off with
  `set_bell`; the OSC 9 notification needs `set_notify(true)` and an unfocused window, `set_focus` from the focus events; a terminal that never reports focus stays "focused" and sends none;

  Write)` writes the bell and the notification. `notification_bytes(run_id)` is `ESC ] 9 ; ham: Cline needs you (run 01M5287J) BEL` from fixed words and a run id that passes the ULID check, so no
  text an engine or a transcript wrote can reach the terminal through it (`Alert::write_to` builds the bytes itself; the struct carries no text). Numbers are held without overflow, and a context of 99.5 percent

- `config_edit`: comment-keeping edits of a TOML file. It is pure: it takes the text of a file and returns the
  new text, reads and writes no file, adds no dependency (it uses the spans of `toml::de::DeTable::parse`) and knows no key names.
  - Interface: `apply(text, edits, rank) -> Result<Outcome, Refusal>`; `Edit::Set { path, value }` and `Edit::Clear { path }`; `EditValue` (`Bool`, `Int`, `Float`, `Str`,
    `StrList`); `Outcome::Unchanged` and `Outcome::Changed(String)`; `Refusal::NotToml { line, column }`, `Refusal::Unsupported { line, reason }` and `Refusal::NotProvable`.
    `path` is the key as the file spells it (`["run","goal"]` is the key `goal` of `[run]`; a name that holds a dot is one key). `rank(&[String]) -> usize` orders new top-level
    keys (the registry supplies it; a lower number sits earlier; `usize::MAX` means the key is not in the registry and never follows a new key). Edits apply in order, each to
    the text the one before it made.
  - What it does: it replaces the value span of an existing key, inserts one line for a new key or removes the lines of an unset key, and every other byte stays (comments, blank
    lines, order, quoting, the file's own LF or CRLF). Setting the value a key already has, or clearing a key that is not there, is `Unchanged` (a value is the same when it reads the same: `'x'` and `"x"`, `0.90` and `0.9`, `0x10` and `16`; floats compare by their bits, so `-0.0` and `0.0` differ). A new top-level key goes before the
    first existing top-level key that follows it in rank order (comment lines directly above that key stay with it), else after the last top-level assignment, with none above the
    first table (and a blank line after it) or at the end. A new key in an existing table goes after its last key, or after the header line of an empty table. A new table is
    appended at the end after one blank line (a blank line that already ends the file is that line). Unset removes the key's line with its trailing comment and keeps comment lines; a table left with no key and no comment goes with its
    header and the blank line before it (when no blank line stands above the header, the first blank line after the table instead). Setting and then clearing a new key or table restores the original bytes of a file that ends with a line break and no blank line (a first
    top-level key put above the tables leaves the blank line that went with it; a blank line that ended the file went with the table). A file without a final newline gets one before appended text.
  - Values: a string is always a basic double-quoted string with escapes (control characters, line and paragraph separators and the characters `sanitize::marker` names, which are
    the bidirectional, zero-width and other invisible ones, are written as `\uXXXX`, or `\UXXXXXXXX` above U+FFFF); a float must be finite and always has a fraction or an exponent; a string list is written on one line; a key is bare when it is made of letters, digits, `_` and `-`,
    else quoted.
  - Refusals: a dotted key, an inline table, an array of tables, a value where the path needs a table, or a path that names a table is `Unsupported` with the line of that construct
    (line 0 when the edit itself is at fault: an empty path, a float that is not finite), and nothing changes; the same constructs elsewhere in the file do not stop an edit of a plain
    key. A file that is not TOML, starts with a byte order mark or holds a NUL is `NotToml` with line and column (columns count characters), never with the source line.
  - Proof: after each edit the new text is read again with `toml::from_str::<toml::Table>`, both trees are flattened (floats by bits, empty tables kept) and the new tree must equal
    the old tree plus exactly the intended change (an empty table above the edited key may appear or vanish; a value there may not). Otherwise the result is `NotProvable` and the caller keeps its text. The hidden
    functions `apply_with_shifted_value_span` (moves the value span) and `prove_pair` (the oracle on two given texts) let a test see the proof refuse.
  - Spans: the `toml` crate keeps the flags of a table (dotted, implicit, inline) and of an array (array of tables) private, so the module reads them from the spans: a standard
    table's span is its header text and starts with `[`, an inline table's starts with `{`, an implicit table has the span of one key segment, and an array of tables has the span of
    its first header, which is also the span of its first element. `tests/config_edit_spans.rs` pins these facts for the exact `toml` version of `Cargo.toml`.
  - Left to the caller: the key in the spelling the file uses (the module has no alias table, never rewrites a key name and never creates a second spelling); the 64 KiB size cap
    (the reader's); the re-read and SHA-256 compare before the rename, the atomic write, the mode and symlinks.
  - Tests: `tests/config_edit_spans.rs` (the span facts), `tests/config_edit.rs` (the rules on golden files in LF and CRLF, hostile values, the proof), `tests/config_edit_prop.rs`
    (generated documents and edits checked against a model of the edit; one contiguous block of changed lines; fixed point; add then remove; `HAMH_PROP_CASES` raises the 1,500 cases).

The changed files are `ChangedFiles`: `Unavailable` reads `Changed files: unavailable (no verified list was recorded for this delivery)`, a recorded empty list reads `none (the delivery changed no path)`, and a list reads `Changed files: "path" (added)...` with each path JSON-escaped as data, at most 40 shown and `(omitted n more)` for the rest. `harness_prompts` is the number the run's own events record (`RunView.harness_prompts`: goal-loop continues, provider retries, fresh-session starts); the line says it is a count of events. `compose(user_text, &digest, &inputs)` puts the user's text first, then the digest, then Cline's final message only when `Inputs.cline_final` is set. `cline_block(message, nonce)` is that message cut to `MAX_FINAL_CHARS` (1,500) characters (a cut says so on its own line), labelled `written by Cline, untrusted` and fenced with the draft's random word. `add_cline_message(box, message, nonce)` is the key's work: it appends the block after everything in the box, so the person's edits stay; a second call is `AddRefused::Already` (no toggle, so no edit is lost), a message that holds the random word is `NonceInMessage` (the caller makes another word) and a blank one is `NoMessage`. `confirmation(run, head, source_target)` is the second Enter's panel text: the commit, the source run and its target, the target of the new run and that it is a new billable run. The new run's target follows the source's: a repository (`cc:<name>` or `new cc:<name>`) is followed on the same repository with a pull request, named with the branch `harness/<run>` it targets while that holds the delivered commit, the branch of the earlier pull request when that was merged or deleted, and the conflict when the branch was moved; anything else (s3-only, or a target not known yet) is a zip on the branch `harness/<new run id>`, no pull request. The words must match the job `ham::tui::send` starts. `start_key` is `fu-` and 32 hex digits of the SHA-256 of the source run id, the seed commit and the prompt, each prefixed with its length. `header(head)`, `OFFER`, `NOTE` and `RUNNING_OFFER` are the words the screen shows. The start is the TUI's `Job::StartFollowUp` (`ham::tui::ext`, tests `crates/ham/tests/followup_start.rs`). `follow_up_target(source, run)` is the target of `ham continue` when the line names none, `target_name` and `target_words` spell a target for the shell line and the preview, `continue_target_line` is the line `ham continue` prints before it starts, and `continue_preview_tail` ends the preview of a typed `/continue` (tests `tests/command_continue_target.rs`).
- `messages`: the client side of message control, pure.

It names the original message. It names the session shown. Any other state returns `ConfirmError::NotConfirmable`.

  `explain_refusal(status, code, message)` sets box words and text handling. A definitive answer restores the text to the box. `no-message-control` reads "Cline is not waiting for an answer; /cancel stops the run and keeps the work". `question-open`, `run-finished`, and `run-sealed` have their own words. The limits have their own words. The confirmation errors have their own words.

- `runname`: the 5 to 7 word name a run shows in the Runs list. Pure functions with no dependency besides `sanitize`, `redact` and `utility`; the call to the model belongs to the caller (`run-session`). A run name is display text only (root invariant 1): never an S3 key, branch, zip or folder name, pull request title, shell argument or outcome label.
  - Request. `system_text()` is `assets/run-name-system.txt` without its final newline; its version is `PROMPT_VERSION` = `rn-1`, a test pins its SHA-256, and a change is a new version measured again on the live model. `MAX_TOKENS` = 64, `STOP` = `</title>`. `redacted_prompt(prompt)` (it lives in `utility` and `runname` re-exports it, like `word_count`) strips control bytes and escape sequences first and hides credential shapes second, so an escape byte inside a key cannot keep the redactor from seeing it. The order is a contract: hiding first would leave a key that a colour reset (CSI), an OSC 8 hyperlink, a backspace or a NUL cuts in two, because the redactor reads characters and the stripper then joins the pieces. `tests/runname_plan.rs` pins it (`redacted_prompt_strips_escapes_before_it_hides_credentials`, and `credentials_split_by_escape_bytes_never_reach_the_model`, which cuts an AWS key id and a GitHub token with each of the four at every position and between every pair of characters, near the start and across the cut at character 2,000, and requires `redacted_prompt` and the user turn to equal those of the unbroken credential). `plan(prompt)` builds on the shared `utility::excerpt` and `utility::is_short` and returns `Plan {ask, reason, user_text}`: the user turn is `<request>`, the redacted text (whole up to 3,000 characters, else its first 2,000 and last 1,000 around the 7-character mark `\n[...]\n`) with `&`, `<` and `>` escaped, `</request>` and the instruction, at most `MAX_USER_TEXT_CHARS` = 12,100 characters for any prompt. `ask` is false with reason `short_prompt` for fewer than 4 words (fewer than 8 characters when the text is mostly Chinese, Japanese or Thai); the user turn is built either way.
  - Judge. `judge(reply, redacted_prompt)` decides whether the utility model's reply may become a name. It has 19 steps in a fixed order, and the first failure is a `Reason` with a fixed code (`REASON_CODES`, 37 codes, `Reason::as_str`; a stop reason other than `stop_sequence` is `Reason::Stop(StopKind)`). The steps: only `stop_sequence` counts (`stop_<reason>`, `no_text`); a raw reply over 400 characters (`raw_too_long`); on the whole raw reply, before anything is extracted, an escape sequence or control character (`control_chars`), an invisible character (`invisible_chars`), a credential shape (`credential_shape`) and a word over 40 characters (`long_token`), which are the four checks of `utility::guard_raw` (the 400-character limit stays the name's own, and `stored_shape`, behind `accept_stored` and `check_stored`, runs the same guard on a stored name); exactly one `<title>` tag or one clean line (`untagged`); `NONE` or nothing (`none`); a second line (`multiline`); markup, a variable, a mention or a link (`markup_or_link`); decoration and emoji are cleaned; meta text (`meta`); verified, tested, gated or evaluated when the prompt does not hold that word (`outcome_word`); four consecutive words of the system text (`echoes_instructions`); more than 64 columns (`too_wide`); length (`too_long`, `too_short`), with `squeeze` for 8 to 10 words; a name that shares no stem, two-digit number or two-character sequence with the prompt (`ungrounded`); all capitals become sentence case; any character outside letters, digits, blank and `- _ . + # / & ' ( ) ,` (`charset`). The rejecting steps reject and never clean. Last, the name is read the way `check_stored` reads a stored name: its shape, then the length rule of the script it ends in (the squeeze and the cut at 20 characters can turn a mixed Latin and Japanese or Thai name from a spaced name into an unspaced one). So every `Ok` name passes `check_stored(name, prompt)`; a name that breaks the length rule is `too_long` or `too_short` and the run keeps its seed. The result is `Judged {name, squeezed}`.
  - Fixed by tests where the research text left room: a reply of 11 words or more is `too_long` before the width rule can shorten it; a piece with no letter or digit (a lone `-` or `&`) is dropped, since it is not a word; the squeeze also drops trailing function words while more than 5 words remain; the outcome words are matched as whole words; for scripts written without blanks the length is counted in characters (8 to 20, more are cut at 20; fewer only for a prompt of fewer than 15 characters) and the width check waits for the cut; the 40-character word rule counts the tag too, so a reply of `<title>` and more than 33 such characters with no blank is `long_token`.
  - Seed and stored names. `seed_name(head)` is the name built from the stored prompt head (the first 2,000 characters) with no model and no network. It picks the line that asks (an ask marker such as "what I want", else the first prose line of 3 or more words; fenced code, headings, code lines and stack frames are skipped; a link or an address ends the clause), drops the polite opening, takes up to 7 words (up to 20 characters of an unspaced script) and cleans them. The limits (count, sentence case for all capitals, 64 columns) run again on their own result until it stops changing, because the 64-column cut can change the script of the seed; the count rule is that of the script the seed ends in. The constant `UNTITLED` (`Untitled coding run`) stands in when nothing is left or when the result still fails a check of a stored name that needs no prompt; that last check also stops a key split by an invisible character or a brace, which the redactor cannot see and the character filter joins again. It is never stored; the client and the server feed it the same bytes. `accept_stored(name)` (no prompt needed) and `check_stored(name, prompt)` (adds the length rule) are the checks a name passes again when it is read back: no control or invisible character, no credential shape or long word, one line, no markup, at most 64 columns and 256 bytes (`display_width`: wide East Asian and emoji characters count 2, combining marks 0), only the allowed characters. `word_count` counts the pieces of a text that hold a letter or a digit.

# crates/harness-core

## Purpose

This crate holds pure harness logic shared by direct runs. It reports diagnostics for engine processes that have ended. Each diagnostic includes the process exit and a scrubbed stderr line. Both appear in a failed turn's error text. The crate includes the secret redaction used by that diagnostic. It also holds `redact`, a shared linear-time redactor for text that arrives whole or in pieces; agentd's transcript writer uses it. It also loads engine profiles from `engine/profiles/*.toml`. Those profiles are bundled at build time.

## Ownership

`crates/AGENTS.md` owns this crate. `agentd` uses `engine_diagnostic` and `engine_profile`. `run-session` uses `engine_profile::bundled_profile`.

## Local Contracts

- Pure functions: no I/O, clock or randomness except through explicit arguments. The one
  exception is `engine_profile::{load_profile, load_profiles}`, which read profile files
  (`BUNDLED` is read at build time by `build.rs`).
  `engine_profile` uses `harness-protocol` types; the other modules are crate-local.
- `refusal`: `redact` replaces URL user information, authorization
  schemes, secret-named assignments, AWS access key ids, JWTs, PEM private keys and any run of 40 or
  more token characters mixing upper case, lower case and digits with `<redacted>` (hex digests and
  paths stay).
- `engine_diagnostic`: the text agentd appends to a failed turn's `error` when an engine's output closed: `append(base,
  body)` makes `<base> [engine process: <body>]` (`SEPARATOR`), `strip(error)` returns agentd's own text (the first separator decides, so no
  engine byte moves the cut, and only the two texts agentd writes for the engine's pipes, `the engine closed its output` and `engine I/O: ...`,
  are cut at all, so an engine's own error text that holds the separator is read whole; `split(error)` returns that text and the diagnostic apart, and `with_note(error, note)` adds a sentence ahead of the diagnostic, so the diagnostic stays the last part of the text and `strip` keeps the note; a separator inside the note, which holds paths the engine chose, is rewritten so it cannot end the cut early), `stable(text)` keeps the text and the exit
  part and drops the stderr part (the same exit with another tail is the same text). `scrub(raw, cut)` turns the end of an engine's stderr log (the last
  `STDERR_WINDOW_BYTES` = 4,096 bytes; a cut window loses its partial first line, and a cut window with no line break is `long_line` and
  shows nothing) into a `StderrTail`: terminal escapes, control, invisible and bidirectional characters removed, and these replaced: lines of base64 only; presigned query strings; the shapes in the next bullet (URL user information, credential headers, keys that name a secret, flags, `.netrc`, Maven XML, Docker `"auth"` entries, and any whole word of 40 or more standard-base64 characters that holds a `/` or `+` and mixes upper case, lower case and digits, unless it is a path); then `refusal::redact`, hex digests
  of 32 or more characters, provider token prefixes, `_authToken`-style keys and bare account ids. The tests build every stand-in at run time and
  count a surviving piece of a secret as a leak (`tests/engine_diagnostic.rs`). `unreadable_body(exit, why)` words a log agentd could not read within the same bound. `error_body(exit, tail)` is the body that goes into the turn's `error` text (the exit and the `headline`, the last error-shaped line, at most
  `ERROR_BODY_CHARS` = 150 characters) and `log_body` the runtime log's (the exit and the scrubbed tail, at most `LOG_TAIL_CHARS` = 1,500). No
  I/O: agentd reads the file and reaps the process.
- `engine_diagnostic` scrub rules, all in `engine_diagnostic.rs`; `redact_named` applies them in this order:
  - URL user information: `redact_url_passwords` replaces user information that holds a password with `<redacted>` up to the `@` before the host; the host and path stay. It covers an empty user (`redis://:secret@cache`), a raw `@` or `/` in the password and percent-encoded passwords: the user information ends at the last `@` of the run that does not follow a `/` (`last_at_not_after_a_slash`; an `@` after a slash starts an npm scope or a path part), and a raw `/` counts when the authority is `user:rest` and `rest` is not a port. A bracket skips the check only for a closed IPv6 host. `git@host`, `bob@example.com`, npm scopes (`/@babel/core`), `localhost:5173/@vite/client`, `git+https://...repo.git@v1.2.3` and IPv6 hosts stay. A user name with no password stays when `plain_account_name` accepts it (at most 24 lower-case letters and hyphens: `git`, `deploy`, `x-access-token`); a name with a digit, upper case or an underscore is redacted as a possible token.
  - Credential headers: `CREDENTIAL_HEADER` (`Authorization`, `Proxy-Authorization`, `Cookie`, `Set-Cookie`, `X-Amz-Security-Token`, `X-Api-Key`, `X-Auth-Token`) redacts the value to the end of the line, to the closing `'` of a quoted command-line argument, or, when the value is in single quotes (`{ cookie: 'sid=...' }`, Node's printout of a header object), to its closing quote. The value cannot start with a blank, so the blanks after the colon cannot backtrack into it. An array value (`set-cookie: [ ... ]`, and under any strong key `'set-cookie': [ ... ]`, `secrets: [ ... ]`) goes to its closing bracket (`array_end` counts nested brackets across lines; an array that never closes goes to the end of its line or to the start of a secret key inside it, which takes its own value). A header whose value is a token scheme word alone takes the token on the next line.
  - Keys that name a secret: `KEY_VALUE` finds a key, a separator and a value; `redact_keys` scans by hand and `key_outcome` returns `Keep`, `Replace` or `Resume`; the scan goes on at the value of a match that stays, so a key inside it (`-DDB_PASS=...` on the line after a short label) is found. A double-quoted or single-quoted value ends at its first quote that a backslash does not escape (`{"Authorization":"Digest username=\"bob\", response=\"X\""}`, `{"password":"a\"b"}`); the alternatives for a backslash-led opening quote (a key inside a JSON string) and for a value that ends in a lone backslash remain the fallback.
  - A label in front of a second key: when the value of any key is itself a key that names a secret (`second_key_at`: a key name and a separator, also after a scheme word; the quoted name of a key; or a quoted text whose closing quote is the opening quote of the second key's value, which a stray quote makes), the label stays as it is and the scan resumes at the second key, so `pass: password: <secret>` keeps both names and loses the secret. When the second key starts inside a quoted value after other text (a stray quote paired the two: `password="C:\dir\" token="<secret>"`) and the label would take its value, that text goes with the label's value. A value that is no secret key stays the label's value.
  - Schemes: after any secret key an unquoted value may start with a word of `SCHEME_WORDS` (bearer, basic, digest, negotiate, ntlm; any case) and the credential follows it (`authorization=Bearer <token>`). For a key with the part `authorization` or `auth` (`is_authorization_key`), `authorization_value_end` also reads `TOKEN_SCHEMES` (token, apikey, api-key, key, bot, jwt, dpop, ssws, splunk, gnap, privatetoken, vapid) with the token after a blank or on the next line (`scheme_token_end`; a next-line word that ends in a colon is a new message, and a word that starts a secret key with its separator attached or set off by blanks, as in `key authorization=Bearer` or `key signing_key = x`, is that key, not a token; a token that only ends like a key name, as in `...Pw =#`, stays a token) and `PARAMETER_SCHEMES` (digest, aws4-hmac-sha256, oauth, hawk, signature, scram-sha-256) with everything to the end of the line or to the closing `'` of a quoted argument. The sentence exemption of the key rule does not apply to such a key.
  - Short secret words: `SHORT_SECRET_WORDS` (pass, pwd, pw, pat, auth, bearer) count as a whole part of a key (`DB_PASS`, `MYSQL_PWD`, `GITHUB_PAT`, `REDIS_AUTH`, `dbPass`, `ldapPw`), as do a compound that ends in `key` (`OPENAI_KEY`, `openaiKey`) and webhook names (`SLACK_WEBHOOK_URL`: the URL is the credential). The `D` of a JVM property is not part of a lone short word (`-Dpass=...`, `property_key`). These keys are ambiguous, so `key_outcome` decides, with `key_parts` splitting at `_`, `.`, `-` and at camelCase, digit and acronym boundaries. The value must be on the same line, and it stays when `plain_value_of_a_short_key` finds it plainly not a credential: empty, a bare structure opener (`[summer2026]` is a value), a status word, a number of at most 5 digits (only under the lower-case key `pass` and in a host:port form with the colon against the number; `pw: 1234` may be a PIN), a path for the exact key `PWD`, a path under a well-known root for the key `pwd` (`WORKING_DIRECTORY_ROOTS`), a number with a unit of at most two characters under a key whose last part names a number (`NUMERIC_KEY_KINDS`: `auth_port=8080`, `pass_rate=0.95`), a value with a dot or a slash under a key whose last part names a place (`PLACE_KEY_KINDS`: `auth_host=db.example.com`) and a path under `s3Key`. A double colon right after the separator joins the parts of a path (`tests/test_auth.py::test_login`, `auth::tests::x`) and stays. A key whose last part is a kind or a state (`SHORT_KEY_KINDS`: `auth_method`, `pass_through`) and a key whose word before `key` says what it is for (`KEY_KINDS`: `primary_key`, `cacheKey`, `public_key`, `kms_key`) stay.
  - Invisible characters: `invisible` removes every Unicode format character (Cf), the other default-ignorable code points, the variation selectors, the whole tag block U+E0000 to U+E0FFF (tag characters carry hidden ASCII text) and the fillers (U+3164, U+FFA0, U+115F, U+1160, U+2800) before any rule runs, so they are gone from the one-line body and the log line.
  - Paths: `looks_like_a_path` keeps a run of base64 characters readable in the word rule and in the base64-only-line rule when it has a slash and no plus sign, at least 65 percent of its letters and digits are lower case (a secret has about 41 percent), and it has a file extension right after it (a dot and 1 to 12 letters or digits) or at least 3 slashes. A long Java source path with a file extension stays. A 40-character secret with slashes stays redacted, with a measured exception: among 3,000,000 random 40-character base64 keys, 0.043 percent pass as a path when an extension follows the key directly and 0.0018 percent with 3 slashes and no extension.
  - Limits: the scrub does not cover a base64 blob wrapped over lines, a PEM body tail line, a secret split over lines, a value with blanks (`password: a b`), a secret named in a sentence, a password argument without a secret-named flag (`mysql -p<pw>`, `mysql -p <pw>`, `sshpass -p`, `redis-cli -a`, `ldapsearch -w`, `sqlcmd -P`, `docker login -p`, `keytool -storepass`), Gradle `password 'x'`, Kubernetes name/value pairs, YAML block scalars (`password: |`), a standalone `hooks.slack.com` URL or `sk_live_` value, an ambiguous short key at the end of a line (it does not take the next line), a raw `?` in an https password and a protocol-relative `//user:pw@host`. Some readable lines are still redacted: `pat: /regex/`, a source line such as `let pass = ...` and `auth_user: bob`.
  Tests: `tests/engine_diagnostic.rs` (every stand-in is built at run time); `tests/engine_diagnostic_plant.rs`, a planted-secret property (a secret in one of 17 shapes with random noise around it fails when 8 characters of it survive in the tail, the error body or the log body; `ENGINE_DIAGNOSTIC_PLANT_N`, default 20,000, and `ENGINE_DIAGNOSTIC_PLANT_SEED`); `tests/engine_diagnostic_fuzz.rs`, a property test over random stderr (no panic, one line, the bounds hold, no invisible character survives; `ENGINE_DIAGNOSTIC_FUZZ_N`, default 2,000).
- `engine_profile`: `parse_profile` / `load_profile` / `load_profiles` / `validate_profile` /
  `resolve_launch` / `hidden_paths_union` over `harness_protocol::engine_profile::EngineProfile`.
  Checks: schemaVersion 1, name = file stem and an engine name
  (`harness_protocol::common::Engine`), gate `QG-*`, a binary SHA-256 of 64 lower-case hex digits when set, ACP stdin pipe and CLI stdin null, known
  placeholders only, no credential env keys, repo-relative hidden paths, unique `K<n>` rows with
  valid pass rules, scoped rows with a trigger. `build.rs` compiles every
  `engine/profiles/*.toml` into `BUNDLED` (rerun when the directory changes): `bundled_names`,
  `known_engine(name)` (a shape error, or `NoProfile` naming the bundled profiles) and
  `bundled_profile(engine)` are how the boundaries without profile files on disk (`run-session`) know every engine,
  so an engine is added by its profile and fixtures plus a rebuild. `tests/real_profiles.rs` loads the committed
  profiles and `tests/bundled_engines.rs` pins the bundled set. The optional `[mcp]` table (`check_mcp`) is checked by
  `tests/profile_mcp.rs`: `via = "none"` takes no other member, `via = "file"` needs `path`, `template` and `maxResultChars` (`McpFields`); the
  path is `{dataDir}/` or `{configDir}/` and then plain names (`McpPath`; an unknown placeholder is `Placeholder` with the field `mcp.path`); the
  template is plain names under `MCP_TEMPLATES_ROOT` = `engine/profiles/templates` with no placeholder (`McpTemplate`); the cap is
  `MCP_MIN_RESULT_CHARS` = 1,000 to `MCP_MAX_RESULT_CHARS` = 16,000 (`McpMaxResultChars`); `shadow` holds at most 32 names of 1 to 64 characters
  without a space (`McpShadow`). A plain name is not empty, not `.` or `..`, and holds no brace or control character. The checks are lexical;
  agentd, which renders the file as root and gives it to the engine user, opens the destination without following a link.
- `redact`, the new shared redactor module, lives in `src/redact.rs`. `Redactor` finds secret shapes through `spans` and `redact`. It uses regular expressions from the regex crate, without backtracking. It is pure, and its work grows linearly with text length. It also provides `redact_with_secrets` and `redact_checked`. `redact_checked` withholds text it could not check. It returns `RedactFailed`, the unchecked-text error, instead. `Stream` redacts text arriving in pieces through `push` and `finish`. It holds back a trailing window of at least 256 bytes. The transcript writer uses 4 KiB. The window moves back to a word start. It also moves before any secret shape the cut would split. A secret split across pieces is never released whole or in part. A shape held past `max_hold`, the holding limit, is hidden by force. `Cont`, continued hiding, hides the rest of that shape. Existing `refusal::redact` and `engine_diagnostic` rules stay unchanged. The recorder does not yet use the shared redactor. `tests/redact.rs` contains 26 tests. One test measures how time grows with document length. It uses 250 KB and 1 MB source-like documents. Every secret-shaped test stand-in is built at run time in memory.

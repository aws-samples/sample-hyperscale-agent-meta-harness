# crates/research-api

## Purpose

The research route of a direct run. Cline researches the web with Tavily and downloads public GitHub
repositories for context while the VM firewall stays as it is: the VM calls the private API under `/internal/research/*` with its session
credentials and this crate answers, as two Lambda functions in the stage account.

## Ownership

Owned by `crates/AGENTS.md`. Deployed by the control stack (`infra/lib/stacks/research.ts`, instantiated by `control.ts`) as
`hamh-<stage>-research-api` and `hamh-<stage>-research-job`, arm64, built with `cargo lambda build --release --arm64` (one package, two
binaries). The wire types are `harness-protocol` `research`.

## Local Contracts

- Two binaries, one library. `research-api` (`src/bin/research-api.rs`, lambda_http, API Gateway REST v1 events) serves the five routes `harness_protocol::research::route::ALL`; `research-job` (`src/bin/research-job.rs`, lambda_runtime) takes a `JobEvent {run, agent, jobId}` from an asynchronous invoke and runs `jobs::run_job`. Environment: `lambda::api_env` (`RESEARCH_TABLE_NAME`, `HARNESS_BUCKET`, `TAVILY_SECRET_ID`, `RESEARCH_JOB_FUNCTION`, `RESEARCH_PROVIDER` (`auto`, `tavily`, `tavily-keyless`, `agentcore` or `fixture`), `HAMH_STAGE_KIND`, `RESEARCH_STAGE_RATE_PER_MIN`, `WORKER_SESSION_ROLE_NAME`, the optional `HAMH_STAGE` (the stage name for the metrics' `Stage` dimension: 1 to 32 lower-case letters, digits or hyphens, `direct` when unset or empty, a bad value stops the function at start by name), and for `agentcore` and `auto` `AGENTCORE_GATEWAY_URL` and the optional `AGENTCORE_SEARCH_TOOL`) and `lambda::job_env` (`RESEARCH_TABLE_NAME`, `HARNESS_BUCKET`); a missing variable stops the function at start with its name and makes no AWS call, and `fixture` is refused unless `HAMH_STAGE_KIND` is `test`.
- Every call goes through `handler::handle`, in this order: identity (`identity::parse_caller`: an assumed-role session of the worker role in the API's own account, run a ULID, agent `direct`; anything else is `disabled`), the run's policy row (`policy::active`: missing, switched off, expired or invalid is `disabled`, read on every call so switching research off stops a running run), one tick of the run's calls-per-minute window (`limit_rate`, counted for every operation so that what a misbehaving caller can spend or write is bounded), the operation (`ops`), and one audit object written last (`audit`; none for `limits`; a failed audit write fails the call). The error body is `ResearchError`; the status and the exit code come from `ResearchErrorCode`.
- Ports and tests. `ports` holds the traits (`Table`, `Blobs`, `Invoker`, `Clock`, `Provider`, `ArchiveSource`); `aws` implements `Table`, `Blobs` and `Invoker`; the `testing` feature adds `fakes` (in-memory stand-ins with the real rules: counters are conditional, an object is never replaced, a job moves only from the states it is in). Logging: one JSON line per request (`lambda::log_line`) with the operation, the run, the status, the error word, the time and the request id, never a body, a header, a key or fetched text; and, for the keyed Tavily provider only, the Embedded Metric Format lines of the `METRICS` contract below.
- Known limits of this build. Idempotency of search and fetch is not atomic: two simultaneous calls with one key may both run (the counters still bound the run) and the stored answer is the first writer's. A refused call before the policy row is read (identity, policy, rate, unknown route) and every `limits` call write no audit object; every other call writes one, and a failed audit write fails the call although its effect happened. A job lost between its creation and its start reads as `failed` `not_started` after 2 minutes and the caller uses a new key. Counters and sequences live 14 days while a run lasts at most 9 hours. The stage-wide Tavily rate is first come, first served and `research-job` has no reserved concurrency. The provenance gate records what the run saw; it is not an authorisation boundary (a seen page can name any public address, and the URL checks are lexical).
- JOB: `archive::filter_archive(gz, paths, limits) -> Result<Filtered, Fail>` filters the archive. The archive module is `src/archive/`. `mod.rs` contains the filter. `tar.rs` contains the strict streaming tar reader and deterministic writer. `filter.rs` contains the pure rules. Stream gunzip, then tar, one entry at a time. Use flate2 zlib-rs without the `tar` crate. Hold only the kept files, the compressed input and the output in memory. Each kept file is at most 1 MiB. Read the commit id from the pax global header's `comment` record. Require 40 lower-case hex characters. The single first path component is the top directory. An entry outside that directory is malformed. Output paths are relative to the repository root. `Filtered`, the filter result, holds `commit`, `top_dir`, `tar_gz`, and `files`. It also holds `dropped`, `licence`, `read_bytes`, and `unpacked_bytes`. Sort `files`; include sha256 and size for each file.
- JOB: Keep only regular files. Record every other entry in `dropped`, the dropped-entry list. List at most 200 entries, in archive order; when more are dropped the last entry is `{path: "*", reason: "<n> more entries dropped"}`. Use reasons from `archive::reason::ALL`, the fixed reason table. Its 23 words are pinned by `tests/job_archive.rs`. The drops for a zero byte, a backslash, a control, zero-width or direction character, bytes that are not UTF-8, an empty part, a path over 256 bytes and a sparse entry, and the printable form of the listed name, are pinned by `tests/job_archive_names.rs`; `tests/job_odd_names.rs` runs the job over such archives (a tab, a long path, no name; names with spaces at their ends are kept as written) and checks the item manifest validates. Drop symlink, hardlink, device, fifo, sparse, and unknown entry types. Drop names with invalid UTF-8, a NUL, a backslash, or any other control, zero-width, direction or separator character (`unsupported-character`; `filter::is_unsupported_name_char`), absolute names, and names containing a `..`, `.`, or empty component. Drop names over 4,096 bytes and any path below the top directory over 256 bytes (`name-too-long`; the item manifest's `MAX_PATH_CHARS`), so the manifest never refuses a kept path. The dropped list shows every name printable, at most 256 characters, and `(empty name)` for an empty one (the manifest needs a path in each dropped entry); a file with an odd name never fails the download. Exclude directories named `.git`, `.github`, `node_modules`, `target`, or `dist` at any depth. Record one dropped entry per excluded root (a nested `node_modules` directory is one entry, not one per file). Drop files outside `paths`, the requested path prefixes. A prefix ending in `/` names a directory. Any other prefix names a file or a directory. Empty `paths` keeps everything. Drop `.env` and `.env.*`. Drop `id_rsa`, `id_ed25519`, `id_ecdsa`, and `id_dsa`. Drop `*.min.js`, `*.min.css`, and `*.map`. Drop files over 1 MiB without reading them into memory. Drop files containing a NUL in the first 8,000 bytes. Drop text files containing a private-key block in the first 8 KiB. The block starts with a `-----BEGIN ... PRIVATE KEY-----` line. Drop text files containing a line over 2,000 characters. Keep a Git LFS pointer as the small pointer text. Honour pax `x` headers for `path` only. Refuse a pax `size` record. `GNU.sparse.*` marks the entry sparse. Refuse pax blocks over 64 KiB. Refuse GNU `L` and `K` blocks over 4,096 bytes. A path listed twice is malformed, also inside an excluded directory and as a directory entry; a file and an entry below the same name (a file named `docs` and an entry inside a directory `docs`, in either order) are malformed. A directory, link, device or fifo entry that declares data (a non-zero size) is malformed. A global pax header that carries `size`, `path` or `GNU.sparse.*`, and a pax, long-name or long-link header with no entry after it (whatever it carries), are malformed. Names are not Unicode-normalised.
- JOB: Enforce caps from `ResearchLimits`, the archive limits. `repo_read_bytes` counts every decompressed byte, kept or skipped. `repo_read_entries` counts every header, including pax and long-name headers. Also enforce `repo_files` and `repo_unpacked_bytes`. `repo_compressed_bytes` caps the output. Exceeding any cap returns `too_large`, the cap failure. Damaged or truncated gzip or tar returns `upstream_error`, the archive failure. A missing end marker returns `upstream_error`. A bad header checksum returns `upstream_error`. A missing or malformed commit id returns `upstream_error`. Compare the commit id with any 40-hex top-directory suffix. A differing commit id returns `upstream_error`. An entry outside the top directory returns `upstream_error`. A duplicate path returns `upstream_error`. The gzip input must be exactly one complete member (bytes after it return `upstream_error`), and after the tar end blocks only zero bytes may follow, read through the same cap. Messages name the rule. Never include an entry name or content in messages. Return no partial result. Make the output deterministic. Sort entries by path. Set mtime to 0. Set uid and gid to 0. Set mode to 0644. Use ustar. Use a pax `path` record for names over 100 bytes. Set gzip header mtime to 0. Use fixed gzip level 6. The same files must give the same bytes. Output contains regular files only. Output contains no directory entries. Tests are `tests/job_archive.rs` and `tests/job_archive_prop.rs`. `tests/job_support/` contains a tar builder and independent output reader.
- JOB: `licence`, the licence evidence module, provides `detect(&[LicenceCandidate]) -> LicenceEvidence`. It also provides `select_candidates`, `is_candidate_name`, and `signature_ids`. Read root-level licence files named `LICENSE`, `LICENCE`, `COPYING`, or `UNLICENSE`. Accept any case. Accept an optional doc extension or `-MIT` style suffix. Read declared fields in `package.json`, `Cargo.toml`, and `pyproject.toml`. The result is evidence, not clearance. Match a signature table of 16 licences against normalised text. The table is data. Each licence has one test text in `tests/job_licence.rs`. GNU licences get `-only` or `-or-later` from the notice text. A declared id for the same licence refines that result. One recognised licence gives its SPDX id and `file:<path>`. Several recognised licences give ids joined with ` AND `. Use a declared expression instead when it covers them all. Only unrecognised files give `NOASSERTION`. With no file, a declared field gives its text. Limit that text to at most 128 bytes. Use `declared:<file>` as its source. Nothing gives `NOASSERTION` with source `none`. Read licences from the repository root even when `paths` excludes them or the content rules drop the file, within a budget of 32 files and 4 MiB (`archive::MAX_LICENCE_BYTES`) in all, counted in archive order. A kept file is read in place (`detect_files(&[LicenceFile])`, borrowed) and never copied; a dropped one is moved aside, so the extra memory is at most 4 MiB. Askalono is not used.
- NET: `scan` is pure. `scan_outbound(text, kind, own_key_ids)` refuses credential-shaped text and names only the class (`aws-access-key`, `aws-secret-key`, `github-token`, `gitlab-token`, `slack-token`, `private-key`, `jwt`, `authorization`, `session-key-id`, `long-hex`, `long-base64`), never the text. `ScanKind::Query` refuses hex runs of 32 or more and base64-ish runs (`A-Za-z0-9+/=`) of 40 or more that mix digits with both cases (a run with four or more slashes is a path); `Url` and `RepoPart` percent-decode once, allow a 40-hex commit id, refuse longer hex runs and refuse alphanumeric runs of 48 or more. Own key ids shorter than 16 characters are ignored.
- NET: `check_url(raw, max_bytes)` accepts only `https`, port 443 (or none), a dotted ASCII host that is not an IP address or a private top-level name (`localhost`, `local`, `internal`, ...), no user information, no control characters, spaces or backslashes, and no credential or signature query parameter (`token`, `sig`, `x-amz-signature`, `api_key`, ..., or `key` with a value of 20 or more characters). A written port other than 443, an empty one (`host:`) included, is refused. The canonical form lower-cases the host and drops the default port and the fragment; path and query stay exactly as written, and an explicitly empty query is kept, so one more parameter is a different URL and `/path?` differs from `/path` (the provenance gate compares canonical forms). `extract_links` finds the https links of a page text; `github_repo` accepts `https://github.com/<owner>/<repo>[.git]` only (other hosts `refused_host`, anything else malformed `refused_url`); `clean_text` removes controls, escape sequences, bidi overrides and zero-width characters once before storage.
- NET: `http::HttpClient` is the one outbound client of both Lambdas: hyper with the webpki roots and the ring provider, `https` only, no redirect followed (a 3xx comes back with `location`), the body read only up to a per-call cap (`HttpError::TooLarge`), no idle connections kept, and every resolved address (or IP literal) must pass `globally_routable` or the name is `HttpError::Blocked`. An error names a class and never a URL, a header value or a body, and `Debug` of `HttpRequest` and `HttpResponse` shows the method or status, the host, the header names and the body length, never a header value, a query or a body byte. The `testing` feature adds `http::testing::TestNet` (a fixed host-to-address table; `https` URLs travel as plain TCP to the fake) for the client tests; production code cannot reach it.
- NET: `secret::SecretString` prints `<redacted>` through `Debug` and `Display`, is wiped on drop and exposes its text only inside the crate (`expose`, used for the `Authorization` header). `CachedSecret` keeps a found key five minutes and "no key stored" thirty seconds, serves the last key while the store is down for at most one hour after the last good read (then returns the failure and drops the key; there is no timer, an expired key is replaced or let go at the next access), and `reread_after_auth_failure` reads again at most once every thirty seconds. `AwsSecretSource` reads the `AWSCURRENT` version; a missing version, a missing secret and a blank value are no key; any other error is `upstream_error` with a fixed sentence.
- NET: `tavily::TavilyClient` is keyed (`Authorization: Bearer`, the key's only place in a request) or keyless (`X-Tavily-Access-Mode: keyless`), chosen by construction: a keyed client with no key stored fails `no_key` and sends nothing. A 401 or 403 re-reads the secret once and retries only with a changed key, else `no_key`; 429 is `upstream_rate_limited` with `retry-after` capped at an hour; every other failure is `upstream_error` with the status and an excerpt of at most 200 characters in which the key is replaced by `<redacted>`. A keyed client discards unread any answer whose raw body repeats the key (fixed `upstream_error`; the body of a 401 or 403 is never read, so those two are exempt), and after a refusal it always compares the key now cached with the refused one and retries once when they differ, also when another caller's re-read opened the 30 second window. The module prints nothing (a test pins that); it reports to the injected `Metrics` sink (`METRICS` below).
- NET: `providers::build_provider` chooses `tavily`, `tavily-keyless`, `agentcore` or `fixture` (the four words that pin a provider; `auto` is `build_stage`, next bullet) from the stage configuration (`agentcore` needs the HTTP client and `ProviderDeps.agentcore`, the gateway settings, and no secret). The fixture provider answers from canned data (the `is-plain-obj` set, generic pages on `docs.example.org` and `blog.example.org`) and exists only when the stage kind is `test`. `github_source::HttpArchiveSource` downloads `https://github.com/<owner>/<repo>/archive/<ref>.tar.gz`, follows exactly one redirect and only to `https://codeload.github.com`, sends no credential, stops at the caller's cap (`too_large`) and maps 404 to `not_found`, 403 and 429 to `upstream_rate_limited` and the rest to `upstream_error`.
- METRICS: the health of the stored Tavily key as CloudWatch metrics. `metrics` holds the port (`Metrics`, one method `record(Event)`, no-op default `NoMetrics`), the `Event` enum (`KeyRefused`, `RateLimited`, `PlanLimit`, `KeyLoaded { stored_at_ms }`) and `EmfMetrics<W, C>`, which writes one Embedded Metric Format line per event to `W` (the bin passes standard output, the Lambda's log) with `C`, a `ports::Clock`, for the line's `_aws.Timestamp` (integer milliseconds) and the age. Namespace `Hamh/Research` (`metrics::NAMESPACE`), dimension `Stage` (`metrics::DIMENSION`, the value is `ApiEnv.stage`), one directive per line, one number per line: `TavilyKeyRefused`, `TavilyRateLimited`, `TavilyPlanLimit` (unit `Count`, value 1) and `TavilyKeyAgeDays` (unit `None`, days with a fraction, zero for a creation time in the future); `infra/lib/stacks/research-alarms.ts` holds the same strings and `infra/test/research-alarms.test.ts` reads `metrics.rs` to pin them. `TavilyClient::report_status` records one event for each answer by status alone (401 and 403 `KeyRefused`, 429 `RateLimited`, 432 and 433 `PlanLimit`: 432 is Tavily's plan limit and 433 its pay-as-you-go limit, from Tavily's help article "Understanding HTTP errors"), also when the body repeats the key and the answer is discarded; every other status records nothing. `SecretSource::get` returns a `StoredKey` (the secret and `stored_at_ms`, the `CreatedDate` of `GetSecretValue`, so no permission is added); `CachedSecret` keeps that number and hands it on once per read of the store (`take_load`: a cache refresh or the re-read after a refusal, never a cached key, a key served while the store is down, no key or an undated one) and `TavilyClient::report_load` turns it into `KeyLoaded`, at most every 5 minutes while the route is used. Only the keyed client reports: `AnyProvider::with_metrics` hands the sink to the Tavily variant, the keyless client ignores it, and `agentcore` and `fixture` take none. An event holds a status class or a time and a line holds the fixed names, the stage name and a number, never the key, a header, a response body or an address; `metrics.rs` imports nothing of the key, HTTP or scan code and `secret.rs` nothing of `metrics` (pinned by `tests/net_metrics.rs`, with a property test that no line holds the key). A log that cannot be written never fails a call. Tests: `tests/net_metrics.rs`, `tests/net_secret.rs`, `tests/net_providers.rs`, `tests/lambda_glue.rs`.
- AUTO: the research provider `auto`, the default of a stage, chooses the provider for each request. `ports::Stage` is what a deployment holds as its provider: `serve()` returns the provider that serves one call (`Err` when the choice cannot be made), `audit_word()` the provider word of the audit object of a call that uses no search provider, `reports_provider_caps()` whether the limits answer carries the serving provider's own caps. Every `Provider` is a `Stage` that serves itself (a blanket impl), so the four words that pin a provider and every older test are unchanged; `Deps.provider` is a `Stage` and `handler::handle` asks it once for search, fetch and limits, and uses that one provider for the whole call (`ops::search` and `ops::fetch` take it as an argument; the answer, the stored record, the manifest and the audit object name `served.id()`). `providers::AutoProvider<P>` holds the keyed half and the gateway half and applies the one rule through `ports::KeyProbe::key_stored` (the keyed Tavily client answers it from its key cache, `CachedSecret::get`: a found key is kept five minutes, no key thirty seconds; a blank value and a secret with no current version are no key): a key is stored, Tavily; none, AgentCore. It never looks at how an earlier call ended, so a refused key still answers `no_key`, a 429 `upstream_rate_limited` and a plan limit `upstream_error`, and a query never goes to the other provider; a key store that cannot be read, with no key held from an earlier read, fails the call with `upstream_error` and sends nothing (a limits call still answers, without a provider member). Fetch without a key answers `disabled` with the `agentcore` sentence before anything is reserved or sent. Limits on an auto stage name the provider that would answer and lower `queryChars` to its own cap (200 for AgentCore) without raising it (`ops::limits`); the pinned words answer the run's limits as before. `repo` and `job` read no key; their audit objects name `github-archive` (`Stage::audit_word`). An idempotency key is bound to the provider that served the first call (`search_req_hash`), so a retry across a stored or cleared key answers `conflict`. `AnyStage` (`Fixed` or `Auto`) and `build_stage(StageChoice, StageKind, ProviderDeps)` give the Lambda one type; `auto` needs the HTTP client, the key secret and the gateway settings or the function fails at start with `internal`; `AnyStage::with_metrics` hands the sink to the keyed half, so the key events of the METRICS bullet are written while Tavily serves and none while AgentCore does. `lambda::api_env` reads `RESEARCH_PROVIDER=auto` into `ApiEnv.auto` and `ApiEnv::choice()` (`StageChoice::Auto` or `Pinned`; `ApiEnv.provider` holds `agentcore` for `auto`); the word is exact, allowed on every stage kind, and needs `AGENTCORE_GATEWAY_URL`. `auto` is no member of the wire's `ResearchProvider` (harness-protocol is unchanged); run-session reads it as `agentcore` for the policy row. Tests: `tests/route_auto.rs` (the handler over two scripted halves), `tests/net_auto.rs` (the real clients over a fake clock, a fake gateway and recorded Secrets Manager answers) and `tests/lambda_auto.rs`.
- AGENTCORE: `agentcore::AgentcoreProvider` searches AWS's own web index through an AgentCore Gateway with the Web Search Tool connector, with no third-party key. MCP over JSON-RPC 2.0, one POST per message to `AGENTCORE_GATEWAY_URL` (`GatewayTarget::parse`: https, a host `<id>.gateway.bedrock-agentcore.<region>.amazonaws.com`, no port, user information, query or fragment, path `/mcp`), signed with SigV4 by `agentcore::sign_headers` (service `bedrock-agentcore`; the Region is the one in the address and `api_env` requires it to equal `AWS_REGION` when that is set; the function's own credentials, asked from the SDK's provider on every call; the headers `content-type`, `accept` and `mcp-protocol-version` are signed with `host`, `x-amz-date` and `x-amz-security-token`, and are sent exactly as signed). The headers are `Content-Type: application/json`, `Accept: application/json, text/event-stream` (an answer in event-stream framing is read) and `MCP-Protocol-Version: 2025-03-26`, the only version the gateway speaks. One `initialize` runs per instance (a `tokio` `OnceCell`: searches that start together share it, a failed one is tried again, only the fact is cached and no session id), then `tools/call` of `AGENTCORE_SEARCH_TOOL` (default `web-search-tool___WebSearch`) with `{query, maxResults, filters}`: `maxResults` is the request's count (default 5; the gateway takes 1 to 25, the route 10), `filters.domainFilter.include` is `includeDomains`, `filters.publishedDateFilter.from` is the clock minus 1, 7, 30 or 365 days for `timeRange` day, week, month or year; the filters member is left out when the request names none. The query is at most 200 characters (the gateway's cap, counted in characters), kept as this provider's own limit (`Provider::max_query_chars`) and not as the route's `queryChars`: the route refuses a longer query with `usage` right after validation, before the scan, the idempotency lookup and the reservation, so it costs the run nothing and is not written into the audit object. The answer's `content[0].text` is a JSON string `{id, results:[{title, url, publishedDate, text}]}`; a result without a URL is skipped, `text` becomes the snippet (cut to 1 KiB), `"unknown"` is no date, there is no score and no credits, and `id` is the upstream request id of the audit object. The answer is read to at most 512 KiB and the request id of the answer must be the one sent.
- AGENTCORE: Errors. Everything maps to the route's closed words and no text names the gateway address, an ARN or an account.

  | The gateway answers | The route answers |
  | --- | --- |
  | HTTP 200, `isError=false` | the results |
  | HTTP 200, `isError=true`, text with `Error code 429`, `status code 429` (not followed by another digit), `ThrottlingException`, `Too Many Requests` or `Rate exceeded` and no `validation error` | `upstream_rate_limited`, `retryAfterS` 60 (the gateway sends a throttle this way) |
  | HTTP 200, `isError=true`, an `AccessDenied` or `not authorized` text | `upstream_error`: the gateway refused the research-api role, check `bedrock-agentcore:InvokeGateway` on the gateway |
  | HTTP 200, `isError=true`, any other text | `upstream_error` with an excerpt of at most 200 characters (one line, controls removed, addresses, ARNs and account numbers replaced by `<redacted>`) |
  | HTTP 401 or 403, JSON-RPC error -32002 or an `AccessDenied` text in a JSON-RPC error | the same `upstream_error` that names `bedrock-agentcore:InvokeGateway` |
  | HTTP 400 with JSON-RPC -32600 | `upstream_error`: an unsupported MCP protocol version (this provider speaks 2025-03-26) |
  | HTTP 429 | `upstream_rate_limited` with the `retry-after` seconds (capped at an hour; none when it is missing or not a number) |
  | any other HTTP status, a JSON-RPC error | `upstream_error` with the status or the JSON-RPC code only |
  | no answer in time, a refused connection, an answer over the cap, JSON that cannot be read, a mismatched request id, a malformed inner text | `upstream_error` with a fixed sentence |
  | `extract` (fetch) | `disabled`, never a call: this provider cannot fetch a page |

- AGENTCORE: What the route stores. The service terms of the Web Search Tool bar extracting, storing or reproducing results in bulk, so `ops::retained` keeps titles and URLs only for this provider: the stored search record (one object per search under the run's research prefix) and the idempotent answer hold `title` and `url` with an empty `snippet` and no `published` or `score`; the audit object holds the provider `agentcore`, the exact query and the gateway's result id and no result at all. The caller gets the live answer once, with its excerpts and dates. A replay (the same idempotency key and request) therefore returns the same titles and URLs with an empty `snippet` and makes no call and no charge. The hash an idempotency key is bound to includes the provider for `agentcore` (the older providers hash as before), so a key stored under `tavily` is a `conflict` on an agentcore stage and an excerpt that another provider stored is never replayed. `tests/route_agentcore.rs` gives every excerpt a unique marker and looks for it in every stored byte; the live answer holds it (the control). The DIRECT-RESEARCH judges check the same on a live record (E3).
- AGENTCORE: Fetch. A stage whose provider cannot fetch (`Provider::can_extract` is false) answers `fetch` with `disabled` (HTTP 503, `ham-research` exit 3) right after validation, before any URL check, table read or reservation; the audit object says `refused`. `repo` is the GitHub download and does not depend on the search provider. A stage that needs fetch stays on `tavily`.
- AGENTCORE: Which stage. The stage configuration chooses `agentcore`; a caller cannot. `TAVILY_SECRET_ID` is still required by `api_env` because the stack passes it for every provider, but this provider never reads the secret. The research Lambda runs outside any VPC (`infra/lib/stacks/research.ts`), so the gateway's public address passes the client's global-address rule. The role needs `bedrock-agentcore:InvokeGateway` on the gateway. Search costs $7.00 per 1,000 queries (AWS's published price). Not built: a circuit breaker after a throttle; the stage-wide per-minute tick (`RESEARCH_STAGE_RATE_PER_MIN`) is the only brake, and a burst inside one minute can still reach the gateway's own limit. The result list is returned as the gateway ranks it.
- CALLER: `lambda::to_request` turns the identity of an API Gateway event into a caller only when the event looks like one API Gateway made for a worker session: the context has an API id, a stage, a request id, a source address and an access key that starts with `ASIA`; its account is the account of this function (read from the Lambda context's function ARN, which the invoker cannot write); and the invocation carries no client context and no Cognito identity. Anything else has no caller: the five routes answer `disabled`, and the operator's key-state question (which needs no caller) is unchanged. This is validation and not authentication: a principal that may invoke the function can send a copy of a real event, so who may invoke it is settled by IAM (`SECURITY.md`). Tests: `tests/b639_direct_invoke.rs`, `tests/lambda_glue.rs`.
- PAGE: a fetched page is stored as the engine reads it: a notice line that names the delimiter, a begin line, the page text, an end line (`ops::frame_page`). The delimiter is 16 random bytes of the operating system as hex, made for each stored page (`ops::fresh_delimiter` offers values until one is absent from the page; an entropy failure ends the call). The page cap and the cut still apply to the page text and the marker is added after the cut, so the stored body is the text plus a constant few hundred bytes; the storage budget (`context_bytes`), `items[].bytes` and the manifest's `body` describe the stored bytes, and `sourceSha256` stays the hash of what the provider returned. Search excerpts keep their wrapper in `ham-research`. Tests: `tests/b654_page_marker.rs`, `tests/route_fetch.rs`.

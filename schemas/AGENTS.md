# schemas

## Purpose

Contract artifacts: JSON Schema 2020-12 documents and
OpenAPI 3.1 documents generated from `crates/harness-protocol`.

## Ownership

Generated by `crates/harness-protocol` (`export` module); owned by `crates/harness-protocol/AGENTS.md`.
Never edit these files by hand.

## Local Contracts

- Files: `event-envelope.schema.json` (the event envelope), `openapi-v1.json` (the public `/v1` API) and `openapi-internal.json` (the
  `/internal` API), `items.schema.json` (the store items), `evidence.schema.json` (the evidence record header), `engine-profile.schema.json`
  (the TOML files in `engine/profiles/`, validated as JSON after parsing), `runtime.schema.json` (the agentd runtime contract: ping,
  invocation, and the direct invocation request, summary and evidence with the provider failover records `DirectAttempt`, `DirectSwitch` and `DirectFailoverNote`), `orchestration.schema.json` (the harness event payloads: goal
  status and blocked, delivery PR and ready, run completed and aborted, session started) and `tools.schema.json` (the `tools/list` result of the
  harness's tool server: each tool's name, description and `inputSchema` as constants, the failure words and the server name).
- Regenerate with `cargo run -p harness-protocol --bin export-schemas`; the harness-protocol test
  `committed_schema_files_equal_fresh_output` fails when a file here is stale.
- `crates/harness-protocol/tests/schemas.rs` `FROZEN` pins each released version's SHA-256 over these files, so a changed file fails CI
  until a new version is pinned. The crate version (`crates/harness-protocol/Cargo.toml`) is the `info.version` of both OpenAPI documents.
- A change to any file here needs a `harness-protocol` version bump, a contract-test update and an acceptance rerun.
